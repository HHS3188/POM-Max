# Performance Optimization MAX 4.0.0 使用说明

适用环境：**A Dance of Fire and Ice 3.2.0-3.3.1**、Unity 6000.3.10f1、UnityModManager 0.32.5

## 安装

1. 下载 Release 中的 `POM-Max-4.0.0.zip`，用 UnityModManager 安装
2. 或直接下载并运行 `POM-Max-4.0.0-一键安装.cmd`
3. 启动游戏，在 UMM 中启用 **Performance Optimization MAX**

一键安装器会自动读取 Steam 注册表、`libraryfolders.vdf` 和游戏清单，详细展示 V4 更新内容；如游戏正在运行，只结束匹配该安装目录的游戏进程。安装前会校验内置文件，备份原有 `POMMax.dll` 与 `Info.json`，保留 `Settings.xml`，写入失败时自动回滚。

## 档位

### Off

关闭 POM-Max 行为，并恢复启用前捕获的 Unity 画质、异步上传和进程优先级设置。用于兼容性排查。

### MAX

日常重特效谱面的稳定强优化档：

- 目标帧率 240，关闭 VSync 和抗锯齿
- 阻止谱面的 `SetFrameRate` 强制帧率事件
- 大型 PNG/JPEG 自定义纹理按最长边最多缩小 2 倍
- 异步上传缓冲 32 MB，仅在加载阶段提高上传时间片
- DOTween 容量预分配为 1500 Tweener / 400 Sequence
- 游戏进程使用 `AboveNormal`，不改 CPU 亲和性和系统电源计划
- 启用保守的静态装饰位置缓存、着色状态缓存与有效碰撞列表

### EXTREME

仅追求可逆极限性能：

- 目标帧率 10000
- 大型自定义纹理按最长边最多缩小 8 倍，短边不低于 32 像素
- 异步上传缓冲 64 MB，加载阶段使用更高上传时间片
- DOTween 容量预分配为 4000 Tweener / 1000 Sequence
- 降低阴影、实时反射、软粒子、LOD 等 Unity 画质开销
- 使用更短的碰撞列表复核间隔与更高加载阶段上传预算

EXTREME 仍保留全部谱面事件、装饰、碰撞、轨道和动画逻辑。V4 只跳过当前帧可证明未变化的重复计算；发现 Tween、跟随、视差、自定义组件、Shader 效果、补丁冲突或异常时立即走游戏原逻辑。

## 页面与高级参数

- `运行概览`：显示当前档位、FPS、P95/P99 帧时间、每帧 GC 与最近一次加载结果
- `性能档位`：载入关闭、MAX 或极限性能的推荐参数
- `高级参数`：调整遥测窗口、上传时间片、三个装饰热路径、纹理下限与缓存容量
- `诊断信息`：显示游戏程序集标识、模块命中次数、熔断状态、纹理缓存与补丁冲突

切换档位会重新载入该档位推荐值。之后在高级参数中的修改会正常保存，不会在点击“保存”时被档位覆盖。

## 新版纹理路径

旧版会先让 Unity 完整解码，再创建第二张 RGBA 纹理并销毁原纹理，峰值内存较高，也容易导致透明图和黑色装饰异常。

4.0.0 先读取 PNG/JPEG 头部尺寸，再把安全的 `maxSideSize` 交给游戏自己的 `TextureManager.LoadTexture`。文件路径、修改时间和大小不变时复用有界元数据缓存，因此只走一次游戏原生加载路径，并保持宽高比。背景、装饰、边框和碰撞区域按实际缩放比例补偿。

遇到以下情况时只关闭 POM-Max 的纹理模块，其他优化继续运行：

- 检测到 `optimiz`、Iridium 或其他模组也修改 `TextureManager.LoadTexture`
- 连续 3 次纹理预处理失败
- 文件格式不是受支持的 PNG/JPEG，或文件头无法安全解析

## 兼容与回滚

- 不修改 `Assembly-CSharp.dll`、游戏资源、谱面文件或 Together 本体
- 不删除谱面事件、装饰和编辑器数据
- 不替换装饰管理器主循环
- 不在纹理加载过程中强制 GC 或 `UnloadUnusedAssets`
- 不修改输入、音频时钟、判定窗口或谱面运行进度
- 不修改 `Assembly-CSharp.dll`、UnityModManager 或 Together 文件
- 不创建占位纹理，不用黑图掩盖加载失败
- 不节流 OBS、浏览器、Discord 等其他进程
- 不修改 Windows 电源计划、CPU 亲和性和计时器精度
- 每个 Harmony 补丁独立安装，签名变化时只跳过对应功能

禁用模组或切换到 Off 后，会恢复捕获到的 Unity 设置与进程优先级。DOTween 的容量预分配只增加池容量，无法缩小，但不会改变 Tween 语义。

## 优化结果窗口

每次自定义谱面加载完成后显示一次小型汇总：

- 谱面事件与装饰已保留
- 本次加载纹理数和限尺寸数量
- 估算纹理内存节省与缩减比例
- 异步上传缓冲和 DOTween 容量
- 加载耗时

## 故障排查

1. 显示异常时先切到 `MAX` 并重新加载谱面
2. 仍异常时切到 `Off`，确认问题是否来自 POM-Max
3. 检查 UMM 日志中的 `[Compatibility]`、`[TextureOptimizer]`、`[V4/PatchSafety]` 和 `[V4/Evidence]`
4. 提交游戏版本、POM-Max 版本、所选档位、谱面名称和完整 UMM 日志

编译通过只代表静态可用；发布验收还应包括 UMM 加载、真实自定义谱面、死亡重开、返回编辑器和多个分辨率下的运行检查。

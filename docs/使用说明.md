# Performance Optimization MAX Usage Guide

This document explains every setting in **Performance Optimization MAX** and what usually happens when you raise or lower it. The mod is designed for heavy `.adofai` custom levels in **A Dance of Fire and Ice**.

Compatibility is documented in each GitHub Release. Other game versions may work, but they are not guaranteed.

## Profile Order

The profile row is ordered from safest to most aggressive:

`Off` -> `Normal` -> `MAX` -> `OVERDRIVE`

Higher profiles usually improve performance more, but may reduce visuals, limit background apps, or expose compatibility problems in specific custom levels. If decorations disappear, show as blank, or look wrong, lower the profile one step at a time and test again.

### Off

No optimization is applied. Use this when you want the original game behavior or when debugging another mod.

### Normal

Recommended default for most players.

What it does:

- Forces the target FPS if enabled.
- Disables VSync and anti-aliasing if enabled.
- Blocks `.adofai` `SetFrameRate` events if enabled.
- Skips pre-load memory cleanup if enabled.
- Enables the load timeout watchdog if enabled.
- Can disable background video during optimized loads.

Expected result:

- Usually smoother frame pacing.
- Faster restart and level load on large maps.
- Low visual risk.
- Background videos or forced low-FPS level events may no longer behave exactly like the mapper intended.

### MAX

Use this for heavy effect/decor maps when `Normal` is not enough.

What it does in addition to `Normal`:

- Removes heavier filter, bloom, screen, and particle events during decoded level optimization.
- Can cap visual decoration count.
- Keeps the v2 decoration display fix: decoration shader simplification and update throttling are not applied in normal `MAX`.

Expected result:

- Better FPS on maps with many effects.
- Lower risk of blank decorations compared with v1.
- Some visual effects may be missing or simplified because expensive events are skipped.

### OVERDRIVE

`OVERDRIVE` is a separate extreme mode. It is intended for maps that are nearly unplayable without aggressive tradeoffs.

What it does:

- Uses the `MAX` optimization path.
- Aggressively lowers other user-session process priorities when background throttling is enabled.
- Raises the game process priority.
- Requests the Windows high-performance or ultimate-performance power plan while active, then attempts to restore the previous plan when disabled.
- Tries to use all CPU affinity for the game process.
- Keeps the system awake and uses a 1 ms timer while active.
- Applies extra quality reductions such as disabling shadows, reducing pixel lights, disabling soft particles, disabling realtime reflection probes, lowering LOD bias, and reducing texture resolution.
- Enables decoration shader simplification and visual-only decoration update throttling if those options are enabled.

Expected result:

- Maximum performance release available from the mod.
- Other applications may become less responsive.
- Visuals may change more noticeably.
- Some custom levels may show decoration issues. If that happens, turn off `OVERDRIVE`, use `MAX`, or disable decoration shader simplification and decoration update throttling.
- The mod can request higher scheduling and power behavior, but Windows, drivers, laptop firmware, and GPU control panels still decide the final hardware frequency. It does not permanently overclock hardware.

## Runtime Frame Pacing

### Force target frame rate

When enabled, the mod writes the target FPS into Unity and the game's RD frame-rate utility.

Recommended:

- `120` for normal high-refresh monitors.
- `144` or `165` for matching common gaming monitors.
- `240` for high-refresh play and the default mod setting.
- `360+` only if your system can actually maintain it.

What happens if you raise it:

- The game asks for more frames.
- CPU/GPU load can increase.
- On heavy maps, a very high target does not guarantee higher real FPS.

What happens if you lower it:

- Lower power and heat.
- More stable frame pacing on weaker machines.
- Less input/render smoothness on high-refresh monitors.

### Disable VSync

When enabled, Unity VSync is set to `0`.

Result:

- Usually lowers latency and avoids FPS being locked by monitor refresh.
- May introduce screen tearing.
- If tearing is distracting, disable this option or use driver-level sync settings.

### Disable anti-aliasing

When enabled, Unity anti-aliasing is set to `0`.

Result:

- Reduces GPU cost.
- Edges may look sharper or more jagged.
- Usually safe for performance-focused play.

### Block level SetFrameRate events

Some `.adofai` levels use `SetFrameRate` to force a low or unstable frame rate. This option blocks those events.

Result:

- Helps avoid mappers forcing low FPS during gameplay.
- Some intentional visual timing effects may no longer match the original level design.

## Load And Restart

### Skip pre-load memory cleanup

The game normally calls memory cleanup before loading a level. That can block the main thread on large custom levels. This option skips that cleanup during optimized loads.

Result when enabled:

- Faster level loads and faster death restart in many large maps.
- Less white-screen waiting caused by cleanup.
- Memory usage may stay higher until Unity cleans up later.

Disable it if:

- You see memory usage growing too much after many level loads.
- You are troubleshooting crashes that look memory-related.

### Enable load timeout auto-return

When enabled, the mod watches long load/restart operations and returns to a safer scene if the configured timeout is exceeded.

Important limitation:

- If Unity is completely blocked in a synchronous operation, the watchdog can only run after the main thread becomes responsive again. It still helps prevent many long-load cases from continuing indefinitely.

### Max load time seconds

Range: `5` to `600`.

Recommended:

- `20-30`: aggressive. Good if you want quick fallback and do not load extremely large maps.
- `45`: default. Balanced for most large custom levels.
- `60-120`: safer for huge `.adofai` files, slow disks, or many assets.
- `300+`: only if you intentionally allow very long loads.

What happens if you lower it:

- The game returns earlier from suspiciously long loads.
- Very large but valid levels may be aborted too soon.

What happens if you raise it:

- Fewer false aborts on huge levels.
- Longer wait before the mod gives up on a stuck load.

## Level Data Optimizer

These options are applied after a `.adofai` file is decoded. The editor scene is skipped to avoid saving a reduced version of the map.

### Optimize decoded level events

Master switch for event optimization.

Result:

- `Normal`: mostly keeps visuals but blocks selected high-cost behavior such as forced frame-rate events.
- `MAX`: removes more high-cost events such as filters, bloom, screen effects, and particles.
- `OVERDRIVE`: can remove even more visual events.

Disable it if:

- You want the level to look as close as possible to the original.
- A specific map depends heavily on effects that are being removed.

### Disable background video on optimized loads

Background videos are expensive to load and decode.

Result:

- Faster loads.
- Lower GPU/video decode cost.
- The background video will be missing.

### Cap visual decorations

Limits how many non-protected visual decorations remain after level optimization.

Protected decorations include:

- Decorations with hitboxes.
- Decorations with component data.
- Decorations tagged with `[attachToTile]`.

Result:

- Can strongly improve FPS on decoration-heavy maps.
- Can remove some purely visual decorations.
- Does not run in the editor scene.

### Max decorations

Range: `100` to `100000`.

Recommended:

- `5000`: aggressive. Strong FPS improvement, high visual loss risk.
- `10000`: moderate for very heavy maps.
- `20000`: default in v2. Better compatibility with fewer missing decorations.
- `50000+`: mostly preserves visuals, smaller FPS gain.

What happens if you lower it:

- More decorations are removed.
- FPS and load speed can improve.
- Visual completeness decreases.

What happens if you raise it:

- More original decorations remain.
- Fewer visual changes.
- Less performance gain.

### Simplify decoration shaders

In v2 this option only affects `OVERDRIVE`.

Result:

- Skips the original decoration shader update path and uses a simpler visible sprite path.
- Can reduce heavy decoration shader cost.
- Can cause some custom decorations to look wrong or blank. If that happens, disable this option or leave `OVERDRIVE`.

### Throttle visual-only decoration updates

In v2 this option only affects `OVERDRIVE`.

Result:

- Pure visual decorations do not update position every frame.
- Decorations with hitboxes, attached behavior, planet-following behavior, or editor strict mode are protected.
- Can improve FPS on maps with thousands of animated decorations.
- Can make some visual motion look less smooth.

### Decoration update stride

Range: `1` to `8`.

Meaning:

- `1`: update every frame. No throttling.
- `2`: update every second frame.
- `3`: update every third frame.
- `4+`: stronger throttling, more visible stutter risk.

Recommended:

- `2`: default and safest useful value.
- `3`: stronger FPS gain.
- `4+`: emergency use for extremely heavy levels.

## Windows Performance Mode

### Raise game process priority

Raises the game process priority while the mod is active.

Result:

- Windows is more likely to schedule the game ahead of normal apps.
- Other apps may feel less responsive.

### Prevent sleep and use 1 ms timer while active

Keeps the system awake and requests a 1 ms timer while the mod is active.

Result:

- More stable short timing intervals.
- Slightly higher power usage.

### Lower priority of other user-session processes

When enabled with `OVERDRIVE`, the mod repeatedly lowers other same-session process priorities.

Result:

- More CPU scheduling room for the game.
- Browsers, launchers, chat apps, and background tools may become less responsive.
- Protected system processes are skipped.

### Verbose log optimization details

Writes more detail into the UMM log.

Use it when:

- You are testing a map-specific issue.
- You want to see how many events/decorations were removed.

Disable it when:

- You do not need logs.
- You want the least log noise.

# 中文说明

本文解释 **Performance Optimization MAX** 的每个设置项，以及数值调高或调低后通常会发生什么。这个 mod 面向 **冰与火之舞** 中装饰、特效、背景视频、强制帧率事件较多的 `.adofai` 自定义谱面。

兼容性写在每个 GitHub Release 中。其他游戏版本可能能用，但不保证兼容。

## 档位顺序

档位从稳妥到激进依次为：

`Off` -> `Normal` -> `MAX` -> `OVERDRIVE`

档位越高，优化提升通常越强，但也更可能带来视觉副作用、后台应用限制，或暴露某些自定义谱面的兼容问题。如果出现装饰物消失、空白、显示异常，请逐步降低档位测试。

## 推荐用法

- 平时先用 `Normal`。
- 如果谱面特效和装饰很多，再切到 `MAX`。
- 如果 `MAX` 仍然很卡，再用 `OVERDRIVE`。
- 如果 `OVERDRIVE` 出现装饰显示问题，先关闭“简化装饰 shader”和“节流纯视觉装饰更新”，还不行就退回 `MAX`。

## 关键参数

- `目标 FPS`: 推荐 `120/144/165/240`。调高会增加 CPU/GPU 压力，不保证实际帧率一定提高；调低会更省电更稳，但流畅度下降。
- `最大加载时间`: 默认 `45` 秒。调低会更快自动退回，但大谱面可能误判；调高会给大谱面更多时间，但卡住时等待更久。
- `最大装饰数量`: 默认 `20000`。调低会删除更多纯视觉装饰，FPS 提升更明显但画面缺失更多；调高会更保留原谱面视觉，但优化幅度变小。
- `装饰更新间隔`: 只影响 `OVERDRIVE`。`1` 等于不跳帧，`2` 每两帧更新一次，`3` 更激进，`4+` 可能明显卡动画但更省性能。

## 全部设置说明

### 强制目标帧率

开启后，mod 会把目标 FPS 写入 Unity 和游戏内部的 RD 帧率工具。调高会让游戏尝试渲染更多帧，但也会增加 CPU/GPU 压力；调低能降低发热和功耗，但高刷新显示器上的流畅度会下降。

### 关闭垂直同步

开启后会把 Unity VSync 设为 `0`。通常能降低延迟并避免被显示器刷新率锁死，但可能出现画面撕裂。如果你更在意画面稳定，可以关闭这个选项，或者使用显卡驱动里的同步设置。

### 关闭抗锯齿

开启后会关闭 Unity 抗锯齿。GPU 压力会下降，但边缘可能更锐利或更锯齿。对重特效谱面通常是比较稳的优化。

### 阻止谱面 SetFrameRate 事件

有些 `.adofai` 谱面会用 `SetFrameRate` 强制低帧率或特殊帧率。开启后会阻止这些事件生效。好处是避免谱面强制把帧率拉低，代价是某些作者设计的视觉节奏可能不再完全一致。

### 跳过加载前内存清理

游戏原本会在加载谱面前执行内存清理，大谱面上这个过程可能阻塞主线程。开启后加载和死亡重开的等待通常会减少，但多次切换谱面后内存占用可能更高。如果你遇到疑似内存相关崩溃，可以关闭测试。

### 加载超时自动退回

开启后，mod 会监控加载、重载资源、死亡重开等流程。如果超过设定秒数，会尝试退回安全场景或编辑器编辑模式。注意，如果 Unity 主线程完全卡死，同步卡死期间 watchdog 也无法执行，只能等主线程恢复后再退回。

### 优化解码后的谱面事件

这是谱面数据优化总开关。`Normal` 主要保留视觉，只处理强制帧率等行为；`MAX` 会进一步移除滤镜、Bloom、屏幕效果、粒子等高开销事件；`OVERDRIVE` 会更激进。关闭后谱面会更接近原始视觉，但性能提升会变小。

### 优化加载时禁用背景视频

背景视频加载和解码成本很高。开启后能减少加载时间和 GPU/视频解码压力，但谱面的背景视频会消失。

### 限制视觉装饰数量

开启后会限制非保护类视觉装饰数量。带 hitbox、components、`[attachToTile]` 标签的装饰会尽量保留。数值越低，FPS 提升可能越明显，但画面缺失越多；数值越高，原谱面视觉保留越多，但优化幅度变小。编辑器场景不会写入被削减的数据。

### 简化装饰 shader

v2 中只影响 `OVERDRIVE`。开启后会跳过原本较重的装饰 shader 更新路径，换成更简单的可见 sprite 路径。它能减少部分装饰 shader 开销，但也最容易导致某些自定义装饰显示错误或空白。遇到装饰问题优先关闭它。

### 节流纯视觉装饰更新

v2 中只影响 `OVERDRIVE`。开启后，纯视觉装饰不会每帧都更新位置。带 hitbox、跟随星球、贴地、编辑器严格编辑模式等对象会被保护。它能改善大量动态装饰带来的帧率压力，但可能让部分动画不够顺滑。

### 提高游戏进程优先级

开启后，Windows 会更倾向于先调度游戏进程。普通档位会使用较温和的优先级，`OVERDRIVE` 会使用更高优先级。后台软件可能变慢。

### 防止睡眠并使用 1ms 计时器

开启后，mod 激活期间会阻止系统睡眠并请求 1ms 计时器。好处是短时间间隔更稳定，代价是功耗略高。

### 降低其他进程优先级

配合 `OVERDRIVE` 时会反复降低同一用户会话中其他进程优先级，为游戏让出更多调度空间。浏览器、聊天软件、启动器、后台工具可能明显变慢。系统关键进程会跳过。

### 记录详细优化日志

开启后会往 UMM 日志写入更多信息，例如移除了多少事件/装饰。排查问题时有用，平时可以关闭减少日志噪音。

## OVERDRIVE 会做什么

`OVERDRIVE` 是独立极限模式，会尽可能释放性能：

- 使用 `MAX` 的谱面优化路径。
- 提高游戏进程优先级。
- 降低同一用户会话中其他进程优先级。
- 请求 Windows 高性能或卓越性能电源计划，关闭时尝试恢复原计划。
- 尝试让游戏进程使用全部 CPU affinity。
- 防止系统睡眠，并使用 1ms 计时器。
- 降低阴影、灯光、软粒子、实时反射、LOD、贴图分辨率等高开销画质设置。
- 如果开启相关选项，还会简化装饰 shader 并节流纯视觉装饰更新。

注意：mod 能请求更高的系统调度和电源策略，但最终 CPU/GPU 频率仍由 Windows、驱动、电源策略、笔记本固件和显卡控制面板决定。它不会永久超频硬件。

# 한국어 설명

이 문서는 **Performance Optimization MAX**의 모든 설정과 값을 올리거나 내렸을 때의 일반적인 결과를 설명합니다. 이 모드는 장식, 효과, 배경 비디오, 강제 프레임 이벤트가 많은 **A Dance of Fire and Ice** `.adofai` 커스텀 레벨을 대상으로 합니다.

호환성은 각 GitHub Release에 적습니다. 다른 게임 버전에서도 작동할 수 있지만 보장하지 않습니다.

## 프로필 순서

안전한 순서에서 공격적인 순서까지:

`Off` -> `Normal` -> `MAX` -> `OVERDRIVE`

높은 프로필일수록 성능 향상 가능성은 커지지만, 시각적 부작용이나 백그라운드 앱 제한이 생길 수 있습니다. 장식이 사라지거나 빈 상태로 보이면 한 단계씩 낮추면서 테스트하세요.

## 권장 사용

- 기본은 `Normal`부터 사용하세요.
- 효과와 장식이 많은 레벨은 `MAX`를 사용하세요.
- `MAX`로도 부족하면 `OVERDRIVE`를 사용하세요.
- `OVERDRIVE`에서 장식 문제가 생기면 먼저 장식 셰이더 단순화와 장식 업데이트 절감을 끄고, 그래도 문제가 있으면 `MAX`로 낮추세요.

## 주요 값

- `Target FPS`: `120/144/165/240` 권장. 높이면 CPU/GPU 부하가 늘고 실제 FPS 상승이 보장되지는 않습니다. 낮추면 전력과 발열은 줄지만 부드러움도 줄어듭니다.
- `Max load time`: 기본 `45`초. 낮추면 빠르게 복귀하지만 큰 레벨을 너무 빨리 중단할 수 있습니다. 높이면 큰 레벨에 시간을 더 주지만 멈춘 상황에서 더 오래 기다립니다.
- `Max decorations`: 기본 `20000`. 낮추면 더 많은 순수 시각 장식을 제거해 FPS가 더 오를 수 있지만 화면 손실이 커집니다. 높이면 원래 화면을 더 보존하지만 성능 향상은 줄어듭니다.
- `Decoration update stride`: `OVERDRIVE`에서만 적용됩니다. `1`은 매 프레임 업데이트, `2`는 두 프레임마다, `3`은 더 강하게 줄이며, `4+`는 애니메이션 끊김이 눈에 띌 수 있습니다.

## OVERDRIVE 동작

`OVERDRIVE`는 별도의 극한 모드입니다.

- `MAX` 레벨 최적화 경로를 사용합니다.
- 게임 프로세스 우선순위를 높입니다.
- 같은 사용자 세션의 다른 프로세스 우선순위를 낮춥니다.
- Windows 고성능 또는 최고 성능 전원 계획을 요청하고, 비활성화 시 이전 계획 복원을 시도합니다.
- 게임 프로세스가 모든 CPU affinity를 사용하도록 시도합니다.
- 절전을 막고 1ms 타이머를 사용합니다.
- 그림자, 조명, 소프트 파티클, 실시간 반사, LOD, 텍스처 해상도 같은 비싼 품질 옵션을 낮춥니다.
- 관련 옵션이 켜져 있으면 장식 셰이더 단순화와 순수 시각 장식 업데이트 절감을 적용합니다.

참고: 모드는 더 높은 스케줄링과 전원 동작을 요청할 수 있지만, 실제 CPU/GPU 클럭은 Windows, 드라이버, 전원 설정, 노트북 펌웨어, GPU 제어판이 최종 결정합니다. 하드웨어를 영구적으로 오버클럭하지 않습니다.

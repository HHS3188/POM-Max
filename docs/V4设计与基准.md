# V4 设计与基准

## 参考方向

V4 参考了下列开源项目公开展示的工程方向，不复制其私有资源或受限制代码：

- KSPCommunityFixes：生命周期清理、热路径零分配、可独立关闭的补丁与 Profiler 标记
- UnityHeapExplorer：以快照差异和引用根定位资源问题，而不是按名称猜测重复资源
- UniTask：使用 PlayerLoop 和预分配状态避免每帧 Task/协程分配
- Harmony：按补丁所有者审计冲突，并让每个补丁单独失败
- RuntimeUnityEditor / UnityExplorer：仅用于开发期层级和字段验证，不作为运行依赖
- XUnity.AutoTranslator：有界缓存、内容身份校验和多路径回退

项目只吸收通用设计原则。V4 运行时不新增第三方依赖。

## 可证明边界

V4 不通过删除装饰、减少事件、关闭碰撞或改判定获得帧率。三个装饰热路径分别要求：

1. 位置缓存仅作用于无 Tween、无星球/方块跟随、无视差移动、无自定义组件的装饰
2. Shader 缓存仅作用于无滤镜、无遮罩、无混合模式、无 Tween 的视觉装饰，并校验对象身份与状态指纹
3. 碰撞调度只过滤游戏原方法本来立即返回的无效候选，列表按数量变化和时间间隔复核

任何模块连续三次异常后只熔断自身。发现其他 Harmony 所有者修改同一方法时，也只关闭对应快路。

## 对比方法

不能用不同谱面或不同渲染设置比较 Mod。建议在相同电脑上执行：

1. 固定游戏版本、谱面、分辨率、帧率上限和其他 Mod
2. 每个方案冷启动一次，再进行一次不计入结果的预热
3. 从同一检查点运行至少 60 秒
4. 分别记录平均帧率、P95/P99/最大帧时间、每帧 GC、加载耗时和显示完整性
5. 至少重复三次，使用中位数；同时检查 UMM 日志是否存在熔断或补丁冲突

V4 的诊断页和 `[V4/Evidence]` 日志提供上述核心数据及快路命中数。只有同条件数据完成后，才能下“比另一方案更快”的结论。
